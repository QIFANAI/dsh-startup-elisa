## 接入方式

- Host 半侧 `lib/index.js`：
  - 在 `index.html` 首屏注入 `#dsh-elisa-root`、关键 CSS、配置、真实 facts 与 12 秒看门狗。
  - 注册 `/dsh-elisa/splash.css`、`/splash.js`、`/preview/index.html`、`/config`、`/lib/assets/*`。
  - 视频路由支持 `Range`，避免浏览器 seek 失败。
  - 配置写入 `~/.dsh/dsh-startup-elisa.json`。
- 启动层 `lib/splash.js`：
  - 宿主内创建全屏 iframe，加载已验收的 `preview/index.html?embed=1`。
  - iframe 完成时 `postMessage` 回父层；父层淡出、移除 iframe、解锁滚动。
  - 12 秒看门狗，iframe 路由失败或脚本异常时强制放行。
- 预览页 `preview/index.html`：
  - `embed=1` 时从 `/dsh-elisa/config` 读取配置与 facts。
  - HUD 回填 `PROFILE / MODEL / BUNDLES / SANDBOX / SESSIONS`；取不到显示 `—`。
  - `allowSkip=false` 隐藏按钮并禁用 `Esc`；`reducedMotion` 直接走终帧。默认不跟随系统 `prefers-reduced-motion`，只有配置显式为 `true` 才静态。
- 设置页 `lib/client.js`：
  - 注册「ELISA 启动动画」，可调启用、播放时机、允许跳过、减弱动态。
  - Host 注入不生效时（file:// + IPC）可自举加载 splash.css/js。

## 追加排错：desktop 认证失败

本次更新后首次启动出现 `desktop welcome: Web authentication failed`。隔离验证确认与插件无关：卸载插件后仍失败；改用临时 `--user-data-dir` 可正常启动。根因是 DSH Electron 的默认会话 cookie 库陈旧。

处理方式：

1. 完全退出 DSH。
2. 备份并移除 `%USERPROFILE%\AppData\Roaming\@deepseek-ai\dsh-desktop\Network\Cookies` 与 `Cookies-journal`。
3. 重新启动 DSH，认证恢复。
