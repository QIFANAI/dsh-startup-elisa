# P8 · v0.6.0 渲染帧独立观感评审 v1（design-review）


> **仓库说明**：本文是开发期记录的公开镜像，已脱敏本机路径与用户名。文中 `_pN/`、`_p8/`、`_build/`、`_shots-*`、`releases/_superseded/` 等为维护者本机目录，未随公开仓库分发；设计规格、评审与 QA 报告已单独放入 `docs/`。


> 评审对象：Lead 交付的候选实现（v0.6.0，`lib/skin.css` §4.3/§4.8 + `_p8/shots/lead-*`）。
> 判定基准：`_p8/design/reference-research.md` §3 清单 + §4 数值表；用户原话诉求为最终标准。
> 结论一句话：**方向已对（背景可辨、边框已从光点变为整圈连发光环+泛光），不需要重做；但有 1 个高优先伪影 + 2 项高级感差距需要返工，收敛后可交付。**

## 0. 输入与方法

- 背景帧：`lead-before-f00.png`（v0.5 基线）、`lead-ambient-bright-f05.png`（亮峰 t≈3.5s）、`lead-ambient-dim-f11.png`（暗谷 t≈7.7s）、`lead-ambient-dim-f00.png`；指标 `lead-metrics-candidate.json` / `lead-metrics-before.json`。
- 边框帧：`lead-composer-zoom-1600-v4.png`（8 帧 #0/#2/…#13）、`lead-composer-zoom-1536dpr125.png`（6 帧，实机 DPR1.25）、`lead-composer-before.png`（v0.5 光点对照）、`lead-real-f00.png`（1920×1080 实机 1:1）。
- 方法：① 逐帧目检（read_image，含 2×/6×/8× 局部放大）；② 自写 numpy 测量（背景 64×64 块差、边缘亮度剖面、环带 vs 卡内亮度）；③ 只读 `lib/skin.css` 核对实现值。全部临时测量件在 `_p8/design/_tmp-*`（收尾清理）。
- 口径声明：composer 数值由 1.7× zoom 拼图反推几何（±1–2 CSS px）；平滑度需 60fps 成片判定（本轮未验）。

## 1. 总判定

| 用户点名项 | 判定 | 一句话依据 |
|---|---|---|
| ① 背景有「呼吸」动态效果 | **通过（可辨），自然度中** | 亮/暗帧 64×64 块差 5.5–12/255（4.2s 间隔），右缘峰谷比 1.92；肉眼在两帧间明显可辨。但暗侧幅度大于亮侧，有轻微「屏幕调光」感（见 Q1） |

## 3. 三个裁决问题

### Q1 背景呼吸是否肉眼可辨、自然？暗帘会不会读成「屏幕调光」？

**可辨性：通过。** 亮峰 vs 暗谷（间隔 4.2s）64×64 块均值差：主区左 11.9、右 8.6、底 10.9、顶 6.2、侧栏 9.1、左缘 5.5/255；全窗均值 33.1↔21.4（1.55×）；右缘亮度序列峰谷比 1.92、左 1.59、顶 1.35、底 1.74（Lead 指标）。对照 v0.5（1.0–2.5/255、峰谷 1.06–1.26）是质的提升，2 倍速回放必然可辨。

**自然度：中，存在「调光感」风险，但不严重。** 数据依据：亮峰帧相对 v0.5 基线在中心内容区几乎没变亮（main_left 差 0.57/255、main_right 1.43/255），而暗谷帧明显压暗（main_left 12.3、main_right 7.3）——即**呼吸的「亮相」≈ v0.5 基线，主要是「暗相」在动**。在暗色界面里，周期性整体压暗 + 抬亮回到基线，会被一部分用户读作「显示器自动调光/亮度抖动」，而不是「光在呼吸」。
- 缓解思路（按优先级）：
  1. **暗帘深度收 15–20%**：`ea-dim-breath` 0.90 → **0.76**（中心 alpha .14→.10、边缘 .50→.40）。目标：暗谷主区差从 12.3 收到 ~10，全窗峰谷比 1.55→**1.42–1.47**（仍远高于 1.35 判据）。
  2. **让亮层略高于基线**：`.ea-breath` 峰值 alpha 0.40/0.32/0.16 → **0.44/0.35/0.18**（+10%），opacity 峰值 .50→**.52**；目标亮峰主区比基线 **+2–3/255**（而不是 0.6）。峰值提高仅 ~3–5%，对比度仍在预算内（但 g=100 正文对比度必须由 QA 复测，见 §6）。
  3. **把「动」放在空间上**：暗帘是整窗径向渐变，建议再分一点权重给 `.ea-rim`（0.12→0.34 改 **0.14→0.42**）与 blob 漂移，让「暗→亮」伴随边缘光/光斑位置变化，而非单纯明暗。
- 周期建议：目前 dim 是 8.6s **完整周期**、breath 是 8.4s alternate（=16.8s 全周期），两个频率叠加易出现「忽快忽慢」。建议统一为单频呼吸：`.ea-breath` 改 `8.4s` 的 0/50/100 关键帧（不再 alternate），`animation-delay:-4.2s` 与 dim 反相 → 一个清晰「吸-呼」节律；blob glow 7.2–9.6s 保留作纹理层。

### Q2 边框是否已读作「整圈光在流动」而非光点？

**结论：不再是光点（方向正确），但还没到「整圈光在流动」，约完成 65%。**
- 已经做对的：① 全周底环可见（实测底环 luma 59–70，卡片内部 16，任何时刻边框都在）；② 亮头位置沿周长迁移（#0 底中 → #2 底左 → #6 右缘 → #10 底中偏左 → #12 底右），不是固定一点；③ 泛光与环同角度同步，无「双环冲突」；④ 删除 offset-path 光段是正确决定。
- 仍像「光点/光带」的三个原因（按影响排序）：
  1. **峰值过曝纯白（H2，高）**：66° 处 `rgba(255,255,255,.95)`，合成后峰值 luma 255（实测多帧 236–255，clip 到纯白）。纯白 + 1.6px 细线 = 霓虹灯管；高级做法是**暖白 ≤0.72 alpha（合成 luma 190–215）**，白色由泛光承担。
  2. **峰值/底环比过大（H2 同修）**：峰值 255 vs 底环 59–70（2.5–4.0×），暗侧读作「环没亮」，光仍像贴在环上的一条亮物，而不是环本身在发光。
  3. **亮区偏窄 + 尾巴不够长（M1，中）**：30% 阈值亮区 138–375px（7–20% 周长），而「整圈在流」的观感需要任一时刻 30–40% 周长处于亮态（≥600px）；同时头两侧衰减近似对称，缺少彗星方向性。
- 判定标准复核：用户原话「边框本身的动态环绕，不是找一个光点在那里转圈」——v4 已满足「不是光点」，但「边框本身」要求光与环融合（底环+宽光弧+泛光同一色温叙事），当前被纯白亮段破坏。

### Q3 底环 alpha .14–.20 是否过亮/过暗？最终建议值

**不算过亮，反而偏低；真正问题是「底环太暗 + 峰值太亮」的组合。**
- 实测：底环 alpha .14–.20 合成后 luma 59–70，卡片内部 16，环清晰可见（保证「整圈」语义，这个决策是对的，不要退回 .05）。但环呼吸 opacity 降到 .50 的谷相时，底环 luma ≈32，1.6px 细线接近消失 → 呼吸读作「边亮边灭」而不是「边在呼吸」。
- 澄清：我 §4.1 骨架里的 `.05` 是**旋转光场层**的底光（它叠加在另一条静态底环上），不是最终底环 alpha；Lead 保留可见底环的理解正确。
- **最终建议**：底环 0° .14→**.17**、34° .20→**.24**；白热芯 .95→**.72** 且改暖白 `rgba(255,246,240,.72)`；环呼吸 .50→**.58**（峰谷比 1.72，仍 >1.35 且 ≥1.8 可由 halo 补齐）。这样底环谷相 luma ≈ 45–50（可见）、峰值 luma ≈ 195–215（不过曝）、峰值/底环比 ≈2.2–2.6×，观感从「白亮光带」变为「玻璃边里流动的光」。

## 5. 建议的 v5 数值（可直接替换）

## 6. 已验证 / 未验证

- 已验证：背景呼吸可辨性（像素测量+目检）、边框整圈可见性与亮区宽度、泛光几何（内溢伪影实拍定位）、呼吸/旋转周期关系、static/paused 规则仍在、卡片布局未变（Lead 自述 + 帧观感）、v0.5 对照。
