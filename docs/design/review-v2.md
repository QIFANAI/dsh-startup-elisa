## 2. 三个裁决问题

### Q1 H1 是否已关闭？——**是，关闭。**

三重证据：① `metrics-r2.json` `artifact_check`：卡内上缘 2–8px luma 17.29（RGB 28.1,12.5,33.0）≈ 卡内本色，不再有 v1 的内溢亮带；② 我的独立测量（1536-f00，卡顶边内侧 3–9px）：luma 29.8、RGB(56,19,55)，色相与主题绯红一致（v1 缺陷帧为灰蓝 RGB(36,35,52)，G 通道异常抬高）；③ 视觉复核 `crop1536-top/corner.png` + 官方构建 `v6-1600-full-h1-zoom.png`：内缘干净、光晕在卡外。**H1 关闭，无残留。**

### Q2 composer 是否达到「边框本身的动态环绕、不廉价」？——**达到（约 85%，PASS，建议冻结）。**

先澄清口径（Lead 的疑问）：我 §4.1/§3 的「亮区 ≥32% 周长」从来不是「暖白芯半高」口径，而是 **包含彩色长尾的亮区覆盖**（相对底环 +25% 动态范围的周长占比）；暖白芯半高 10–30° 属正常（Apple 2px 环的 hot core 同样窄）。用同一口径独立复算 r2：
- 亮区（+25% 阈值）**70–110°/帧，中位 ≈70°（19% 周长）**，高峰帧 137°（38%）——已达到我 §3 的「20–40%」区间下限并进入 25–35% 甜点区；暖白芯（+50% 阈值）中位 10–20°，与你的 30° luma 半高同量级。**结论：不需要再大幅拓宽。**
- 底环 p50 45.0（谷相可见）+ 亮区 19–31% + 暖白芯 10–20° + 泛光外置：已经同时具备「整圈有光」「亮区在移动」「有方向性头尾」「有泛光」四要素，不再是小光点/短光段，也不再是纯霓虹白线。判定 **PASS（约 85%）**。
- 可交付标准（最终数值，冻结用）：底环 alpha **0.17**（合成 luma 45±3）；暖白峰值 **0.72**（luma 190–200，不得 clip）；亮区中位 **≥70°**、暖白芯 **≤30°**；旋转 **8s linear**；环呼吸 **6.4s alternate .58→1**；泛光 band 全外置（inset −4/pad 4/r 24/blur 7），opacity .18→.55 同相位。
- 若你仍想做最后 1 次微调（**可选，不建议为此再开一轮**）：只把暖白芯从单点扩到 3 点，让白热头 20–26° 内保持较亮，观感更「柔光」而非「白线」：
  `54° .58 → 66° .72（暖白）→ 78° .60`，其余 stops 不动。目标：暖白芯半高 20–26°、峰值 luma 仍 ≤200。

### Q3 背景「屏幕调光感」是否消除？——**可接受（PASS）。**

- 已从 v1 的「亮相≈基线、只暗不亮」改为明暗双向：相对 v0.5 基线亮峰 **+5.08/255**、暗谷 **−3.08/255**；且空间上分区（中心/左缘以亮为主，侧栏/右缘以暗为主）——观感是「光在背景里流动/涨落」，不是整屏均匀调光。r2 16 帧目检也读作极光呼吸，无「显示器自动亮度」感。
- 全窗峰谷比 **1.498**、区域 ratio 1.35–2.01、3.76s 块差 p90 **6.53**、2 倍速回放必然可辨（对照 v0.5 为 1.0–2.5/255、1.06–1.26）——用户诉求「背景有呼吸」已达成。
- 唯一保留项（交给 QA，不改设计）：中心背景亮峰相对 v0.5 基线 **+68%**（中心区 18.0→30.2 luma；会话正文区 +42%）。这是对比度预算的风险点。若 QA 在 g=100 的会话页/设置页测出 <4.5:1，**最小修复**是只降 `.ea-breath` 中心两枚渐变的 alpha（c1 .44→.38、c2 .36→.32，约 −12–15% 峰值），不要动 dim/rim/周期；不要整体回调呼吸。

## 3. 对 review-v1 的一处自我更正（留痕）

review-v1 §3-Q3 写的「峰值 luma ≈195–215、峰值/底环比 ≈2.2–2.6×」中，**2.2–2.6× 算错了**：195.9/45.0 ≈ 4.35×（照 alpha 0.72/0.17 也约 4.2×）。该比值不是有效验收口径——真正决定「是否像光点」的是 ①峰值是否 clip、②亮区周长覆盖、③头尾方向性。r2 三项均达标（峰值 195.9 无 clip、亮区中位 70°、头 41.5°/0.94s 单调+尾侧长衰减），故不影响 PASS 结论；以本条为准，v1 的 2.2–2.6× 作废。

## 4. 剩余验证项（交 QA / 用户实机，不属设计返工）

1. **对比度（最高优先）**：g=100 与 g=50 的会话页/设置页/空页正文 ≥4.5:1（9 组矩阵）；背景亮峰较 v0.5 抬高，重点看会话页灰色次级文字。失败时按 §2-Q3 的最小修复只降 breath 中心 alpha。
2. **60fps 平滑度**：qa-eng 的 composer 局部 3s 成片；重点看 860×120 长边→短边过角（conic 角速度 10.8× 差）是否读作「闪一下」。若明显：把主弧再宽 10–15°（140–168° stops alpha +.04）或旋转 8s→9s，不改结构。
3. **性能**：软件光栅 TaskDuration/FPS（角度动画=主线程重绘，预期集中在 composer 两伪元素 ≈0.2MP/帧）；backdrop-filter 仍 ≤3。
4. **降级与主题**：static/paused/noblur 截图（本轮只看过 g50 与三主题亮峰帧；deepsea/violet 观感 OK，无青/紫偏色异常）。
5. **DPR**：1536/DPR1.25 已验（环 2 device px 渲染干净）；150%/200% 与 4K 未验。

## 5. 结论与建议

- **设计侧：冻结**。H1 关闭；composer 与背景均 PASS；不再建议结构性返工（避免把已达成的高级感反复打散）。可选微调仅剩「暖白芯 3 点」一项，收益小、非必须。
- **交付路径**：进入 QA 终验 → 安装 desktop（先备份）→ 用户重启确认。若 QA 对比度/60fps 任一不过，按 §2-Q3 与 §4-2 的最小修复处理，不需要重开设计轮。
- 用户三条原话对照：①「背景没有呼吸」→ PASS（1.498×、块差 p90 6.53、肉眼可辨）；②「边框不是呼吸动态」→ PASS（p50 峰谷 1.81/p90 2.27）；③「流光是一个光点转圈、很廉价」→ PASS（整圈底环 + 70–110° 流动亮区 + 外置泛光，无光点、无纯白过曝）。
